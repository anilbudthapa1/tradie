# 9. Settings Module — Full & Final

## Main Purpose

The **Settings Module** controls how each business account behaves inside **Tradie Job Manager**.

It stores business-level preferences for:

```txt
jobs
quotes
invoices
tax
payroll
WorkSafe
notifications
security
users
files
reports
integrations
```

Core rule:

```txt
Settings are tenant-specific. Every setting belongs to one business_id.
Only Owner can change sensitive settings.
Employees can only change their own personal preferences.
```

# Database Tables

## business_settings

```sql
id UUID PRIMARY KEY
business_id UUID NOT NULL REFERENCES businesses(id)

timezone TEXT NOT NULL DEFAULT 'Australia/Melbourne'
currency TEXT NOT NULL DEFAULT 'AUD'
date_format TEXT NOT NULL DEFAULT 'DD/MM/YYYY'
time_format TEXT NOT NULL DEFAULT '12h'
language TEXT NOT NULL DEFAULT 'en'
country TEXT NOT NULL DEFAULT 'Australia'
state TEXT

created_at TIMESTAMP NOT NULL
updated_at TIMESTAMP NOT NULL
```

---

## job_settings

```sql
id UUID PRIMARY KEY
business_id UUID NOT NULL REFERENCES businesses(id)

default_job_status TEXT NOT NULL
require_completion_photo BOOLEAN NOT NULL DEFAULT false
require_customer_signature BOOLEAN NOT NULL DEFAULT false
allow_recurring_jobs BOOLEAN NOT NULL DEFAULT true
auto_assign_worker BOOLEAN NOT NULL DEFAULT false
service_categories JSONB
job_priority_options JSONB
cancellation_reasons JSONB

created_at TIMESTAMP NOT NULL
updated_at TIMESTAMP NOT NULL
```

---

## scheduling_settings

```sql
id UUID PRIMARY KEY
business_id UUID NOT NULL REFERENCES businesses(id)

working_days JSONB NOT NULL
working_hours JSONB NOT NULL
travel_time_buffer_minutes INTEGER DEFAULT 20
minimum_booking_notice_hours INTEGER DEFAULT 2

updated_at TIMESTAMP NOT NULL
```

# Security Techniques

Implement:

```txt
tenant isolation with business_id
Owner-only sensitive settings
PostgreSQL RLS
audit logs for every settings update
field validation
default secure settings
secrets stored in secret manager
integration tokens encrypted
deny by default
```

Never expose:

```txt
raw API keys
encrypted secret values
another business settings
internal storage paths
```

---

# Zero Trust Rules

Every settings request must check:

```txt
Is user authenticated?
Does user belong to this business_id?
Is user Owner for business-wide settings?
Is employee only editing own preferences?
Is subscription active/trialing?
Is this setting allowed under current plan?
Should the action be audited?
```
