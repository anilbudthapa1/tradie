Below is the full Authentication Module plan for Tradie Job Manager.
Module Purpose
To verify user identity, protect business data, and ensure every user only accesses the correct company, role, and feature.
This module will protect:
•	customer records
•	jobs
•	invoices
•	tax reports
•	payslips
•	WorkSafe records
•	worker data
We will make it Zero Trust aligned, not “vulnerability-proof.” No app is 100% vulnerability-proof, but we can make it strongly attack-resistant using OWASP/NIST guidance. OWASP ASVS 5.0 is the current application security verification standard, and NIST SP 800-63-4 covers modern digital identity and authentication guidance. (OWASP)

What We Will Implement
1. Email + Password Login
Used as the basic login method.
Technique:
•	store password using Argon2id
•	never store plain password
•	enforce strong password rules
•	login rate limiting
•	failed login tracking
2. Passkey Login
This is the modern feature.
Technique:
•	use WebAuthn / FIDO2
•	user logs in with fingerprint, face unlock, device PIN, or hardware key
•	server stores public key only
•	private key stays on user device
Passkeys are phishing-resistant because there is no reusable password secret for attackers to steal. (WIRED)
3. Multi-Factor Authentication
For Owner/Admin accounts.
Technique:
•	authenticator app OTP
•	email OTP as backup
•	SMS only as fallback, not primary
4. JWT + Refresh Token Session
Technique:
•	short-lived access token: 10–15 minutes
•	refresh token rotation
•	refresh token stored as hash in database
•	secure HttpOnly cookie
•	revoke tokens on logout
OWASP recommends strong session management because session tokens bind authentication to the user’s web activity and access control. (OWASP Cheat Sheet Series)
5. Zero Trust Request Checks
Every protected API request checks:
Is user authenticated?
Is session valid?
Is device/session trusted?
Does user belong to this business_id?
Does user have permission?
Is the requested action allowed?
6. Tenant Isolation
Very important for SaaS.
Every database query must include:
WHERE business_id = logged_in_user.business_id
This prevents one tradie business from seeing another company’s customers, invoices, payslips, or jobs.
7. Role-Based Access Control
Roles:
Role	Access
Owner	Full access
Admin	Manage jobs, workers, quotes, invoices
Worker	Assigned jobs, job notes, check-in/out
Accountant	Tax, bills, invoices, reports
Customer	View own quotes/invoices only
8. Secure Password Reset
Flow:
Forgot password
→ send reset link
→ token expires quickly
→ token stored as hash
→ user sets new password
→ old sessions revoked
9. Device & Session Management
Users can view:
•	active devices
•	login time
•	IP/location approximation
•	browser/device name
They can revoke unknown sessions.
10. Audit Logging
Record:
•	successful login
•	failed login
•	logout
•	password change
•	passkey added/removed
•	MFA enabled/disabled
•	role changed
•	suspicious login attempt

Security Techniques
Password Security
Use:
Argon2id
minimum 12 characters
breached-password check later
rate limiting
account lockout after repeated failed attempts
Token Security
Use:
short-lived JWT
refresh token rotation
token hashing
HttpOnly Secure SameSite cookies
logout revocation
Browser/API Security
Use:
HTTPS only
CORS allow-list
CSRF protection
security headers
input validation
request size limits
generic error messages
Zero Trust Security
Use:
authenticate every request
authorise every action
check tenant every query
log sensitive actions
deny by default
least privilege
