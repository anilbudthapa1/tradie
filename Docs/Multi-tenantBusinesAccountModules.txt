# 7. Multi-Tenant Business Account Module — Final

## Main Purpose

This module allows many businesses to use **Tradie Job Manager** safely in one SaaS platform.

Core rule:

```txt
One business = one tenant
Every user, job, invoice, employee, file, report, payslip, and setting belongs to one business_id.
```

It prevents:

```txt
Business A seeing Business B data
Employee accessing another company’s jobs
Wrong tax/payroll export
Cross-tenant file access
IDOR vulnerabilities
```

---

# What We Will Implement

## 1. Tenant / Business Account Creation

When an owner registers:

```txt
Create business account
Generate business_id UUID
Link owner to business_id
Create default settings
Create trial subscription
Create audit log
```

---

## 2. Tenant Data Isolation

---

## 3. UUID-Based IDs

Use UUIDs instead of sequential IDs.

```txt
business_id UUID
user_id UUID
job_id UUID
invoice_id UUID
customer_id UUID
```

Why:

```txt
harder to guess records
reduces IDOR risk
better for distributed systems
```

---

## 4. Application-Level Tenant Enforcement

Every backend query must filter by current user’s business:

```sql
SELECT * FROM jobs
WHERE id = :job_id
AND business_id = :current_business_id;
```

Never trust `business_id` from frontend.

Bad:

```json
{
  "business_id": "abc",
  "job_name": "Fix sink"
}
```

Good:

```txt
business_id comes from logged-in session only
```

---

## 5. PostgreSQL Row-Level Security

Use RLS from early stage for stronger isolation.

Concept:

```sql
ALTER TABLE jobs ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation_jobs
ON jobs
USING (business_id = current_setting('app.current_business_id')::uuid);
```

This gives double protection:

```txt
Backend tenant check + Database tenant check
```

# Scoped Unique Constraints

Each business should have its own numbering and records.

Use:

```sql
UNIQUE (business_id, invoice_number)
UNIQUE (business_id, employee_code)
UNIQUE (business_id, customer_email)
UNIQUE (business_id, quote_number)
```

Example:

```txt
ABC Plumbing: INV-0001
XYZ Electrical: INV-0001
```

---

# File Storage Isolation

Use S3-compatible storage paths:

```txt
/businesses/{business_id}/jobs/{job_id}/photos/{file_id}.jpg
/businesses/{business_id}/invoices/{invoice_id}/invoice.pdf
/businesses/{business_id}/payslips/{payslip_id}.pdf
/businesses/{business_id}/worksafe/{report_id}/evidence.jpg
```

Rules:

```txt
No public file access
Use signed URLs
Check business_id before generating signed URL
Never expose raw storage paths
```

---

# Tenant-Safe Soft Delete

Do not hard-delete important business records.

Use:

```sql
deleted_at
deleted_by
delete_reason
```

Important for:

```txt
invoices
tax records
payslips
WorkSafe reports
employee records
audit records
```
