# 3. Login / Logout Module — Zero Trust Secure Design

## Main Purpose

The **Login / Logout Module** controls secure access to Tradie Job Manager after registration.

Its purpose is to:

```txt
verify user identity
validate device/session risk
issue secure access tokens
enforce role + business access
terminate sessions safely
record all login/logout activity
```

---

# What We Will Implement

## 1. Login Methods

### Primary Login

```txt
Email + password
```

### Modern Login

```txt
Passkey / WebAuthn / FIDO2
```

### Admin/Owner Extra Protection

```txt
MFA required for Owner/Admin/Accountant
```

---

# 2. Zero Trust Login Flow

```txt
User submits login
→ validate input
→ check account status
→ verify password/passkey
→ check email verification
→ check MFA requirement
→ evaluate device/session risk
→ issue short-lived access token
→ issue refresh token
→ create session record
→ write audit log
→ allow dashboard access
```

---

# 3. Login Security Checks

Before login success, check:

```txt
Is email verified?
Is account active?
Is business account active?
Is subscription/trial valid?
Is user locked or suspended?
Is password/passkey valid?
Is MFA required?
Is login coming from suspicious device/IP?
```

---

# 4. Logout Flow

```txt
User clicks logout
→ revoke current refresh token
→ delete/clear auth cookies
→ mark session as ended
→ write audit log
→ redirect to login page
```

Also support:

```txt
logout from current device
logout from all devices
admin force logout user
```

---

# 5. Token Strategy

Use:

```txt
short-lived access token
refresh token rotation
server-side session record
```

Recommended:

| Token              | Storage                   | Lifetime             |
| ------------------ | ------------------------- | -------------------- |
| Access Token       | Memory or HttpOnly cookie | 10–15 min            |
| Refresh Token      | HttpOnly Secure cookie    | 7–30 days            |
| Refresh Token Hash | Database                  | Until expiry/revoked |

Important:

```txt
Never store raw refresh tokens in database.
Store only token_hash.
```

---

# 6. Secure Cookie Settings

Use:

```txt
HttpOnly = true
Secure = true
SameSite = Lax or Strict
Path = /api/auth/refresh
```

For production:

```txt
HTTPS only
no token in localStorage
no token in URL
```

---

# 8. Risk-Based Login

Assign risk score using:

```txt
new device
new country/location
many failed attempts
impossible travel
TOR/VPN/proxy indicator
unusual login time
admin/owner role
old password age
```

Actions:

| Risk     | Action                         |
| -------- | ------------------------------ |
| Low      | Allow login                    |
| Medium   | Require MFA                    |
| High     | Block temporarily + send alert |
| Critical | Lock account + admin review    |

---

# 9. Brute Force Protection

Add:

```txt
rate limiting by IP
rate limiting by email
progressive delay
temporary lockout
CAPTCHA after repeated failures
generic error messages
```

Use generic login response:

```txt
Invalid email or password.
```

Do not reveal:

```txt
email exists
password wrong
account suspended
```

---

# 10. MFA Login Flow

For Owner/Admin/Accountant:

```txt
password verified
→ temporary login challenge created
→ user enters MFA code
→ verify MFA
→ create session
→ issue tokens
```

MFA options:

```txt
Authenticator app
Passkey
Backup codes
Email OTP as backup
SMS only fallback
```

---

# 11. Passkey Login Flow

```txt
User enters email or chooses passkey
→ server creates WebAuthn challenge
→ browser signs challenge with private key
→ server verifies public key
→ check user + credential
→ create session
→ issue tokens
```

Passkey database stores:

```txt
credential_id
public_key
sign_count
device_name
last_used_at
```

---

# 12. Logout Security

On logout:

```txt
revoke refresh token
clear cookies
invalidate current session
record audit event
```

On logout all devices:

```txt
revoke all active refresh tokens for user
clear current cookie
force re-login everywhere
```

On password change:

```txt
revoke all sessions except current
```

On role downgrade or suspension:

```txt
revoke all sessions immediately
```

# Validation Rules

Login request:

```txt
email required
email format valid
password required unless passkey
request body size limited
invalid fields rejected
```

MFA request:

```txt
challenge_id required
code required
challenge not expired
challenge not used
```

Refresh request:

```txt
refresh cookie exists
refresh token hash matches
session not revoked
session not expired
user active
business active
```

Logout request:

```txt
current session exists
refresh token exists
session belongs to logged-in user
```
