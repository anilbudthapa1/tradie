# 4. Password Reset Module — Secure Design

## Main Purpose

The **Password Reset Module** allows users to recover account access safely without letting attackers take over accounts.

It must protect:

```txt
business owner accounts
admin accounts
worker accounts
accountant accounts
customer accounts
payroll and tax data
invoice data
WorkSafe records
```

---

# What We Will Implement

## 1. Forgot Password Request

User enters email.

System response must always be generic:

```txt
If an account exists, password reset instructions have been sent.
```

Never reveal whether the email exists.

---

## 2. Secure Reset Token

Use:

```txt
random cryptographic token
single-use only
short expiry
stored hashed in database
```

Recommended expiry:

```txt
15–30 minutes
```

Never store raw token.

---

## 3. Email Reset Link

Email contains secure link:

```txt
https://app.tradiejobs.com/reset-password?token=...
```

Rules:

```txt
token must expire
token must be one-time-use
token must be tied to user_id
token must be invalidated after use
```

---

## 4. Reset Password Form

User enters:

```txt
new password
confirm password
```

Validation:

```txt
minimum 12 characters
must not match old password
must not be common/breached password
must pass strength check
```

---

## 5. Session Revocation After Reset

After successful password reset:

```txt
revoke all active sessions
revoke all refresh tokens
force login again
send security notification
write audit log
```

This is critical.

---

# Zero Trust Reset Flow

```txt
User requests reset
→ validate email format
→ rate limit request
→ return generic response
→ if user exists, create hashed reset token
→ send reset email
→ user opens reset link
→ verify token hash
→ check expiry
→ check token unused
→ validate new password
→ hash new password with Argon2id
→ mark token used
→ revoke all sessions
→ send security alert
→ write audit log
→ user logs in again
```

# Security Techniques

## Token Security

Use:

```txt
crypto random 32+ bytes
SHA-256 hash before database storage
single-use token
15–30 minute expiry
delete expired tokens regularly
```

## Password Security

Use:

```txt
Argon2id hashing
password strength meter
password history check
breached password check
minimum 12 characters
deny reused password
```

## Abuse Protection

Use:

```txt
rate limit by IP
rate limit by email
CAPTCHA after repeated requests
temporary block after abuse
generic responses
email flood protection
```

## Session Security

After password reset:

```txt
revoke all refresh tokens
clear all login sessions
invalidate remember-me devices
require MFA/passkey on next login
```

# Important Role-Based Rules

## Owner/Admin/Accountant

For sensitive roles:

```txt
require MFA/passkey after password reset
send security alert email
notify business owner if admin/accountant resets password
```

## Worker

```txt
revoke sessions
notify user
allow normal login after reset
```

## Customer

```txt
revoke sessions
notify user
limit access to own data only
```

# Common Mistakes To Avoid

Do not:

```txt
store reset token in plain text
make token reusable
use long expiry like 24 hours
reveal whether email exists
keep sessions active after reset
send password in email
allow weak passwords
put token in logs
```
