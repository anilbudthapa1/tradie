# 10. Notification Preferences Module — Full & Final

## Main Purpose

The **Notification Preferences Module** controls **who receives notifications, through which channel, and when**.

It supports:

```txt
job reminders
worker assignments
customer booking updates
quote follow-ups
invoice reminders
payment alerts
WorkSafe alerts
payroll alerts
security alerts
subscription alerts
```

Core rule:

```txt
Business-wide notification rules are controlled by Owner.
Employees can only manage their own personal notification preferences.
```

# 4. Preference Levels

## Business-Level Preferences

Controlled by Owner:

```txt
enable/disable notification type
choose channels
edit templates
set reminder timing
choose recipients
```

## User-Level Preferences

Controlled by each user:

```txt
email on/off
push on/off
SMS on/off, if allowed
quiet hours
preferred language
daily summary on/off
```

Employees cannot disable mandatory security or safety notifications.

# Security Rules

```txt
Never expose provider API keys
Do not send sensitive TFN/bank/payroll data in notifications
Mask sensitive invoice/payment details where needed
Mandatory security notifications cannot be disabled
Tenant-check every notification
Rate-limit test notifications
Audit template changes
```

Do not include in SMS/email:

```txt
TFN
bank account number
full payroll details
password reset token text
private file storage URLs
```

Use secure links instead.

---

# Zero Trust Checks

Every notification action checks:

```txt
Is user authenticated?
Does user belong to current business_id?
Is user Owner for business-wide settings?
Is user editing only their own preferences?
Is event mandatory?
Is channel allowed by business plan?
Is recipient allowed to receive this notification?
```

---

# Notification Flow

```txt
System event occurs
→ build event payload
→ check business preference
→ check user preference
→ check mandatory rules
→ choose channel
→ load template
→ render variables
→ queue notification
→ send via provider
→ store delivery result
→ show in-app notification
```
